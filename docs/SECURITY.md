# Security Policy

## Supported versions

| Version | Supported |
| ------- | --------- |
| 3.0.x (Python desktop) | :white_check_mark: |
| 2.x (FastAPI + Tauri) | :x: |

## Reporting a vulnerability

1. Do **not** open a public issue.
2. Email the maintainer (see the GitHub profile of `nishanth-kj`) with the details and a proof of concept, if you have one.
3. You should get a response within a few days.

## REST API exposure

The optional REST API binds to `127.0.0.1` by default. If you expose it on another interface, set `VOXLABS_API_TOKEN` (or the token in Settings). The desktop app refuses to start a non-loopback API without one. All routes except `/api/health` then require `Authorization: Bearer <token>`.

## Voice cloning safeguards

- **Consent.** Cloning requires an explicit, attributed confirmation (who granted it and whose voice it is), which is stored in `voice_consents` with a timestamp. There is no bypass.
- **Revocation and deletion.** Revoking a voice deletes its samples and profile immediately and blocks further use. Deleting a voice removes all of its records and files.
- **Labelling.** Generated audio is flagged `ai_generated` in the library and written with an "AI-generated by VoxLabs" metadata tag. This is a metadata label, not an inaudible watermark; it can be stripped by re-encoding.
- **Local-first.** Online engines (Google gTTS, Microsoft Edge) are disabled unless you enable them in Settings.
